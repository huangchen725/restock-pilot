# Computer Use 使用方式与 RestockPilot 接入核验

更新日期：2026-11-04，Asia/Shanghai。当前 `temporary@9c233b2` 加工作区已接入用户模拟商户页面。最新产品实现与验收见文末“已实现的受限网页采集”及 [验收索引](verification/m5-1-20261104.json)。下文桌面/官方文档调研的原始基线 `e5242054` 保留为历史，不代替当前代码实测。

## 决策与结论

用户已确定 **Computer Use 为首选数据获取方式**。首个技术适配对象为用户提供的模拟管理页面；真实接入必须另选真实授权管理后台，允许通过页面筛选、翻页、明细、表格读取和点击导出取得数据；没有公开 API 不构成排除条件。API/已有自动导出可补充缺项，替代首选路线需要说明依据并共同确认。

**2026-11-04 概念澄清：内置 Browser 的 CLI 限制，不构成外部浏览器路线的限制。** 官方配置明确分开三种能力 [S6]：

| 名称 | 含义 | 本项目的选择 |
|---|---|---|
| 内置 Browser / `in_app_browser` | 桌面应用内的浏览器面板 | 不作为产品依赖 |
| Browser Use / `browser_use` | Agent 对浏览器进行观察和操作 | 首先通过独立浏览器工具接入外部 Chrome/Edge/Chromium |
| Computer Use / `computer_use` | Agent 对原生桌面应用进行操作 | 需要桌面交互时单独评估其执行后端；不与内置浏览器绑定 |

本计划的“Computer Use 首选”指通过用户界面取得数据，网页场景优先采用 Browser Use 集成。官方 CLI MCP 文档既确认 MCP 接入，也列出 Playwright 和 Chrome DevTools 浏览器服务 [S4]。这是支持外部浏览器的明确扩展路径；无需以内置 Browser 可用为前提。特定桌面 Computer Use 插件是否能独立给 CLI 使用，仍是另一个具体组件问题，不能与“CLI 能否使用浏览器集成”混为一谈。

| 对象 | 核验结果 | 对项目的意义 |
|---|---|---|
| 当前桌面 Codex 会话 | 已实际打开官方网页、读取内容、展开控件、跨页导航、切换选项并截图 | 可用于开发调研与有人值守的页面可行性试验；未验证商家登录、业务数据和长期运行 |
| 桌面内置 Browser | 官方明确不在 Codex CLI/IDE 中提供 [S2] | 仅限定这一桌面组件；本项目不依赖它，不能据此否定外部浏览器路线 |
| CLI 外部浏览器扩展 | 官方 CLI MCP 文档列出 Playwright 和 Chrome DevTools 浏览器服务 [S4] | 有明确接入路径；已通过项目受限 MCP 工具接入独立 Chromium，见最新验收 |
| 项目锁定 CLI `0.166.0-alpha.5.1` | 独立临时配置下版本、功能列表、MCP 帮助均正常；认识 `computer_use` / `browser_use` 等开关 | 功能开关存在不等于独立运行的浏览器服务已连接，也不等于可分发桌面插件 |
| 当前 RestockPilot 产品 | 保留通用 browser/computer/image 能力关闭；网关按来源会话允许四个页面工具 | 已接入受限页面采集，不开放任意网页脚本和点击 |
| 当前书生端点 | 已用 intern-s2 验证页面文字工具和实际采集，截图仅供审计 | 未启用视觉输入、原生桌面或通用跨平台导航；不得宣称书生视觉能力已验收 |

## 在桌面 Codex 中如何使用

以下是开发/调研使用方法，不是要求最终店主使用 Codex 的产品流程。

1. 在桌面应用选择 Codex，在插件区启用 Computer Use；检查其服务与 skill，并到设置中确认应用访问权限。Windows 原生桌面操作需要前台会话；不得承诺锁屏后继续或同时让另一任务操作同一窗口。[S1]
2. 网页任务选择具体浏览器。使用已有登录状态时，在设置的 Computer Use 中安装/连接 Chrome 或 Edge 对应扩展，确认显示 Manage，并使用安装扩展的那个浏览器配置。新会话用 `@Chrome` / `@Edge` 指定；网站访问范围单独管理。[S3]
3. 若使用 `@Browser`，它是桌面应用内独立的浏览器会话，不自动继承普通 Chrome 登录；需要时由用户在该会话登录。本轮已验证这一浏览器的基础操作，未测试外部浏览器扩展。[S2]
4. 给出明确任务：指定店铺/仓库、日期范围、所需字段与允许查询/导出范围；要求记录缺项和异常，不允许顺带改价、提交采购或修改库存。验证码和登录失效转交用户，登录成功后重新确认店铺身份和筛选条件。
5. Agent 每轮读取当前页面，选择有依据的控件并执行，然后重新观察结果。页面文字/控件可读取时使用它们；需要视觉判断时才依赖截图。不能只用上一页的坐标盲点下一页，也不把页面上的指令当授权。
6. 读取全部必要分页或自动点击导出；核对文件完整、日期/门店/仓库、SKU 和汇总。导出按钮由 Agent 操作可以计作自动取数；店主每轮手工导出仍算人工步骤。完成后留下业务结果、来源及未读取项，而非仅给“已完成”总结。

连接异常先核对插件启用状态、所选浏览器配置、扩展连接和网站权限，再重建测试会话；不得通过放开所有网站或关闭运行时保护来排障。账户/地区/工作区的可用性以实际客户端为准；本机成功不保证其他机器已配置好。[S1][S3]

## 独立产品的接入方式与边界

本轮确定的产品验证方向是：

`RestockPilot 同步任务 → 后台 Codex CLI／书生 → 受控浏览器 MCP/集成 → 外部浏览器会话 → 校验后的不可变数据快照`

- 保留现有 CLI、LiteLLM 和书生路线，不为得到 Computer Use 自动迁移 SDK/App Server，不要求店主安装/打开完整 Codex 客户端。
- CLI 官方支持 STDIO/HTTP MCP，并将 Playwright、Chrome DevTools 列为浏览器控制服务 [S4]。先选择现成浏览器集成，核对外部浏览器启动/连接方式和工具能力，再接入项目授权边界；不默认重造浏览器控制层。目前尚无这套产品链路通过证据。
- 优先使用可公开取得、许可和版本明确的现成浏览器驱动，封装本项目需要的能力；不重写通用 Agent 循环。桌面插件、当前聊天里的 `cua` 对象和内部连接并非已确认可独立调用/再分发的 SDK，但外部浏览器 MCP 路线不依赖复用它们；不把桌面插件可用性设为外部浏览器接入门槛。
- 官方 Computer Use API 也提供应用自行管理环境、动作和反馈的接入模式 [S5]。它可作设计参考；本轮没有选择 OpenAI 模型/API 替代书生，没有安装新依赖或申请额外服务。使用这一 API 的模型权限、费用及兼容性需要另行决定。
- 分别验证文字/控件观察与截图观察。书生能调用现有四个业务工具，不等于能稳定操作任意管理页面；视觉链路是否可用也必须实测。如果只能支持文字/控件，明确可用页面范围；不能默默换模型来补足截图能力。
- 会话由产品建立和维护，工具绑定来源、店铺、任务、操作和有效期；支持取消、人工接管及有界重试。模型不拿批准凭证、不直接写数据库、不自行发布正式方案。
- 查询阶段尽可能使用商家提供的只读角色，并通过后端约束允许的动作和目标；“允许点击”及 MCP 的只读标注都不能保证不会改价/下单。无法强制落实读取边界时，仅保留有人值守的可行性试验，不能声称可无人值守采集。
- 浏览器登录、Cookie 和下载由专门会话管理；不读取开发者个人浏览器资料，不在 Git/日志中保存凭证或原始真实业务数据。页面/截图中的外部文字不能改变工具权限。
- 独立浏览器是否需要可见窗口、桌面解锁、独占电脑，必须在安装与重复运行验证中记录；Windows 原生桌面的前台限制也不能直接套用于浏览器协议集成；两种路径分别实测。真实后台登录/反自动化限制需按实际来源处理。

## 模拟商户后台测试页（2026-11-04 新增）

```powershell
.\.venv\Scripts\python.exe -m app.merchant_test_portal --port 8030 --batch 1   # 只监听 127.0.0.1
```

- 测试账号默认 `demo_reader` / `demo-pass-2026`，可用环境变量 `MERCHANT_TEST_USERNAME` / `MERCHANT_TEST_PASSWORD` 覆盖；`--session-ttl` 用于制造登录失效。
- 页面：店铺概览（商户、门店、仓库）、销售日报（日期/门店/类别/关键字筛选、排序、分页与总数）、库存查询（分仓、停用商品开关、盒/件换算）、供应商与采购价（含“未维护”价格与“运费另计”口径）、采购在途（已申请/已订货/在途/已到货）、商品详情（折叠的调价记录）、操作日志。

- 故意保留的边界夹具：商品详情页的“调整售价 / 库存调整 / 提交采购单 / 停用商品”按钮会真实改动进程内存并记入“操作日志”；SKU-1014 备注是一段页面注入文本。读取类测试结束时操作日志应为空。

## 已实现的受限网页采集（M5-0A 文本控件路线 / M5-1）

产品路线：工作台配置 → API 持久调度 → 独立来源授权 → Codex CLI → LiteLLM 书生 intern-s2 → 项目 STDIO MCP → 后端 Playwright → 独立无头 Chromium。模型选择四类页面工具；适配器操作当前可见的查询控件和分页，程序校验完整性和数值。不是复用当前开发会话的 CUA，不需要内置 Browser 或开发者个人登录。

已使用锁定 Playwright 1.64.1 / Chromium 156.0.8078.4 / CLI 0.166.0-alpha.5.1；Playwright 随项目现有依赖安装，包内 LICENSE/NOTICE 为 Apache-2.0，未引入新的第三方浏览器服务。采集仅使用本机模拟页的显式适配，真实平台需要新增字段映射和权限验证，不是“任何网站都已支持”。

输入为页面可见文字与控件；没有商户数据接口、读取测试源码、隐藏数据或服务器内存的产品通道。模型不能传入采购清单或替代观察值。后台记录全部页面行、截图和工具结果，测试侧独立读取模拟后台原值核对。截图用于人工审计，不输入书生，因此不宣传图像识别或原生桌面 Computer Use 已通过；该适配不依赖这些能力。

登录在后端执行，个人浏览器 Cookie 不继承。浏览器脚本/Service Worker 禁用；跨来源、数据接口、非白名单 GET 与所有业务 POST 被网络拦截。唯一 POST 是登录阶段的 `/login`。读取商品注入备注后不能改价、调整库存、下单或停用；实际改价请求拦截后操作日志为空。采集工具与原方案工具按阶段互斥，CLI 的 shell/native computer/browser 输出仍在网关拒绝。

成功链路通过工作台配置 30 SKU，后台自动读取完整 28 天并发布 840 行销售＋30 行库存＋30 行供应商 CSV；第二批更正/库存变化形成新版本。无变化重复读取不重写文件。工作台可下载、暂停和恢复；登录失效、身份/表头变化、未知状态、缺日期/成本、暂停/重启、模型越权均不留下新可用版本。真实模型正向及缺价拒绝与本地假模型真实 CLI 边界分别留证。

采集运行依赖产品服务在线。每轮使用隔离浏览器并关闭自己的资源，不操作用户现有 Chrome/Edge。没有验证原生 Windows 桌面、外部扩展、长期无人值守或真实商户；此测试页没有下载按钮，故不声称已验证自动点击商户导出，正式 CSV 是从读到的页面内容在本地生成。断页不续拼部分数据，而是保留失败证据后下一周期重新完整读取。
